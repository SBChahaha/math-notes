01基本概念与稳定性总纲

排序：把一组记录按关键字递增（或递减）重新排列。趟：一次完整的「扫描/调整」过程。
内部排序：数据全部在内存中完成；外部排序：数据太大，需在内存与外存间多次交换（§9）。
比较类排序的下限：任何基于关键字比较的排序，最坏情况至少需要 $\Omega(n\log n)$ 次比较——所以堆排序/归并/快排的 $O(n\log n)$ 已是天花板（基数排序靠「不比较」突破）。
稳定性（必考）：排序前后，关键字相同的元素相对次序不变，则称该排序算法稳定；否则不稳定。
例：$\{49_1,\ 38,\ 49_2\}$ 排序后若仍为 $49_1$ 在 $49_2$ 前 ⇒ 稳定。
八大算法稳定性速记口诀：「快些选堆」不稳定——快速、希尔、简单选择、堆排序不稳定；其余（直接插入、冒泡、归并、基数）稳定（折半插入作为插入类变体同样稳定）。
为什么要关心稳定性：多关键字排序——先按次关键字排、再按主关键字稳定排序，可保持次关键字内部有序（如「按成绩排序」前已按学号排好）。

02直接插入与折半插入插入类

（1）直接插入排序

思想：把待排元素逐个插入「已排好序的前缀」中——前 $i-1$ 个有序，将第 $i$ 个从后往前找到位置并后移。 
void InsertSort(int A[], int n) {      /* A[1..n]，A[0] 作哨兵 */
    int i, j;
    for (i = 2; i <= n; i++) {
        if (A[i] < A[i-1]) {            /* 需要插入才动 */
            A[0] = A[i];                /* 哨兵暂存待插值 */
            for (j = i-1; A[j] > A[0]; j--)
                A[j+1] = A[j];          /* 从后往前后移 */
            A[j+1] = A[0];              /* 落位 */
        }
    }
}
例（{49, 38, 65, 97, 76, 13, 27, 49} 全程轨迹）.

稳定性细节：内层循环条件是 $A[j]>A[0]$（严格大于）——相等时停下，新元素插在等值元素之后，次序不颠倒 ⇒ 稳定 ✓。
复杂度最好（已有序）：每趟 1 次比较、0 次移动 ⇒ $O(n)$；最坏/平均：$O(n^2)$；空间 $O(1)$；稳定。
适用：元素基本有序、n 较小时表现好。

（2）折半插入排序

改进点：定位插入位置改用折半查找（有序前缀上折半）——比较次数从 $O(n^2)$ 降到 $O(n\log n)$；但元素移动次数不变 ⇒ 总时间仍是 $O(n^2)$。 
void BinInsertSort(int A[], int n) {
    int i, j, low, high, mid;
    for (i = 2; i <= n; i++) {
        A[0] = A[i];                    /* 暂存 */
        low = 1;  high = i-1;
        while (low <= high) {           /* 折半定位置 */
            mid = (low + high) / 2;
            if (A[mid] > A[0]) high = mid - 1;
            else low = mid + 1;         /* 相等时往右，保稳定 */
        }
        for (j = i-1; j >= high+1; j--)
            A[j+1] = A[j];              /* 统一后移 */
        A[high+1] = A[0];
    }
}
稳定性：折半遇相等时取右半区（else low = mid+1）⇒ 插在等值元素后 ⇒ 稳定 ✓。

03希尔排序分组插入

思想：取一个增量 $d$，把相隔 $d$ 的元素分成一组，组内做直接插入排序；然后缩小增量（如折半递减），重复分组排序；最后 $d=1$（全局插入排序）收尾。
为什么有效：大增量时元素「大步跳跃」快速接近目标位置，小增量时「小步微调」——整体移动次数大幅减少。
例（{49, 38, 65, 97, 76, 13, 27, 49}，增量 4 → 2 → 1）.
① d=4 分组：（49,76）（38,13）（65,27）（97,49）——每组 2 个元素各自插排： 组内结果：49,76 ｜ 13,38 ｜ 27,65 ｜ 49,97；按原位回填：$[49,\ 13,\ 27,\ 49,\ 76,\ 38,\ 65,\ 97]$（下面记为 A）。 ② d=2 分组：奇位序列 $(49,27,76,65)$ 与偶位序列 $(13,49,38,97)$：
  · 奇位插排：$27,49,65,76$；偶位插排：$13,38,49,97$；
  · 回填：$[27, 13, 49, 38, 65, 49, 76, 97]$；
③ d=1（全局插入排序）：$[27,13,49,38,65,49,76,97]\to[13,27,38,49,49,65,76,97]$ ✓。
不稳定的原因：相隔多组的相同元素可能被「跨组交换」颠倒次序——如两个 49 在 $d=4$ 时就分属不同组独立排序——因此希尔排序不稳定。
复杂度：时间约 $O(n^{1.3})$（增量设计相关，最坏 $O(n^2)$）；空间 $O(1)$。注意：增量序列的最后一项必须是 1（否则未真正排好）。

04冒泡排序相邻交换

思想：从前往后比较相邻两元素，逆序就交换——每趟把当前最大者「冒泡」到末尾；$n-1$ 趟后有序。优化：某趟没有发生任何交换 ⇒ 已经有序，提前结束。 
void BubbleSort(int A[], int n) {          /* A[0..n-1] */
    for (int i = 0; i < n - 1; i++) {
        bool flag = false;                 /* 本趟是否发生交换 */
        for (int j = 0; j < n - 1 - i; j++)   /* 已沉底的不再比 */
            if (A[j] > A[j+1]) {
                swap(A[j], A[j+1]);
                flag = true;
            }
        if (!flag) return;                 /* 提前结束 */
    }
}
例（前两趟完整轨迹）. 上例数组 $[49,38,65,97,76,13,27,49]$：
第一趟（97 沉底）：(49,38)→换；49&65 不换；65&97 不换；97&76→换；(97,13)→换；(97,27)→换；(97,49)→换： $$[38,49,65,76,13,27,49,\ \mathbf{97}]$$ 第二趟（76 沉底）：(38,49)(49,65)(65,76) 不换；(76,13)→换；(76,27)→换；(76,49)→换： $$[38,49,65,13,27,49,\ \mathbf{76},\ 97]$$ 继续到第五趟得到全程有序 $[13,27,38,49,49,65,76,97]$（相等元素不交换 ⇒ 稳定）。
复杂度与性质 最好（已有序 + flag）：1 趟 $n-1$ 次比较 ⇒ $O(n)$；最坏/平均 $O(n^2)$；空间 $O(1)$；稳定。
邻接比较的天然优势：链表也能冒泡（与插入排序一样属于「适配链式存储」的一类）。

05快速排序平均性能之王

思想（分治）：① 取一个枢轴（通常首元素）；② 一趟划分：比枢轴小的挪到左边、大的挪到右边，枢轴落位；③ 对左右两个子区间递归——枢轴自此不再参与。
「每趟划分」的成果：枢轴元素被放到最终位置（这是「快排一趟后的状态」类题的关键）。
int Partition(int A[], int low, int high) {
    int pivot = A[low];                 /* 枢轴（挖坑法） */
    while (low < high) {
        while (low < high && A[high] >= pivot) high--;
        A[low] = A[high];               /* 大的留在右、小的填左坑 */
        while (low < high && A[low] <= pivot) low++;
        A[high] = A[low];               /* 小的留在左、大的填右坑 */
    }
    A[low] = pivot;                     /* 枢轴归位 */
    return low;
}
void QuickSort(int A[], int low, int high) {
    if (low < high) {
        int pos = Partition(A, low, high);   /* 划分 */
        QuickSort(A, low, pos - 1);          /* 排左半区 */
        QuickSort(A, pos + 1, high);         /* 排右半区 */
    }
}
例（一趟划分完整轨迹：枢轴 49）. $A=[49,38,65,97,76,13,27,49]$，low=1、high=8：

递归继续：左区 $[27,38,13]$（枢轴 27）⇒ $[13,27,38]$；右区 $[76,97,65,49]$（枢轴 76）⇒ 划分后 $[49,65,76,97]$。全程结果：$[13,27,38,49,49,65,76,97]$ ✓。
复杂度与三条高频结论 · 平均时间 $O(n\log n)$（划分较均衡时，递归深度 $\log n$、每层划分 $O(n)$）；
· 最坏 $O(n^2)$：输入「基本有序/逆序」且固定取首元素作枢轴时，每次划分一边空——退化成冒泡级别；
· 空间：递归栈平均 $O(\log n)$、最坏 $O(n)$；不稳定（跨越式交换破坏相等元素次序）；
· 优化：随机枢轴 / 三数取中（取左、中、右的中位数）可避开最坏情形。
「快排一趟结果」题的写法：把枢轴放最终位置、左边全比它小、右边全比它大即可——左右两半内部不必有序（这正是很多同学丢分的点：写成了「整体更有序」的中间态）。

06选择排序：简单选择与堆排序选择类

（1）简单选择排序

思想：每趟在无序区中选出最小者，与无序区第一个元素交换——有序区每趟扩大 1。 
void SelectSort(int A[], int n) {
    for (int i = 0; i < n-1; i++) {
        int min = i;                       /* 记录最小元下标 */
        for (int j = i+1; j < n; j++)
            if (A[j] < A[min]) min = j;
        if (min != i) swap(A[i], A[min]);
    }
}
例（前两趟）. $[49,38,65,97,76,13,27,49]$：
① 第 1 趟：最小 13（位置 6）与 49 交换 ⇒ $[\mathbf{13},38,65,97,76,49,27,49]$；
② 第 2 趟：剩余最小 27（位置 7）与 38 交换 ⇒ $[13,\mathbf{27},65,97,76,49,38,49]$。
不稳定的证据（举一反三）：对 $[49_1, 38, 49_2, 13]$，第 1 趟把 13 与 49₁ 交换 ⇒ $[13,38,49_2,49_1]$——两个 49 次序颠倒 ⇒ 不稳定 ✓。
简单选择的两条「恒定」：比较次数恒为 $\frac{n(n-1)}2$（与初始状态无关，任何输入都这么多比较）；移动次数很少（最多 $n-1$ 次交换）——它适合「元素较大、移动昂贵」的场景，但时间上永远是 $O(n^2)$。

（2）堆排序（本节的硬骨头）

大根堆：完全二叉树且每个结点关键字 $\ge$ 两个孩子。顺序存储（1 起编号）：结点 $k$ 的孩子是 $2k$ 与 $2k+1$（0 起编号则是 $2k+1$ 与 $2k+2$——写代码先确认编号基准）。
两步走：① 建堆（从 $\lfloor n/2\rfloor$ 号结点倒着到 1，各做一次「向下调整」）；② 反复「取堆顶 ↔ 末尾交换 + 调整剩余部分」。
void AdjustDown(int A[], int k, int len) {   /* 大根堆：k 向下调整 */
    A[0] = A[k];                             /* 暂存（A[0] 作临时位） */
    for (int i = 2*k; i <= len; i *= 2) {    /* 沿较大孩子下行 */
        if (i < len && A[i] < A[i+1]) i++;   /* 取较大孩子 */
        if (A[0] >= A[i]) break;             /* 已满足堆序 */
        else { A[k] = A[i];  k = i; }        /* 孩子上移，继续下探 */
    }
    A[k] = A[0];
}
void BuildMaxHeap(int A[], int len) {
    for (int k = len/2; k >= 1; k--)         /* 自底向上 */
        AdjustDown(A, k, len);
}
void HeapSort(int A[], int len) {
    BuildMaxHeap(A, len);                    /* (1) 建大根堆 */
    for (int i = len; i > 1; i--) {          /* (2) 反复取最大 */
        swap(A[1], A[i]);                    /* 堆顶换到有序区前端 */
        AdjustDown(A, 1, i-1);               /* 剩余部分重新调整 */
    }
}
例 1（建堆全轨迹：[53,17,78,9,45,65,87,23]）.

注意：建堆是从 $\lfloor 8/2\rfloor=4$ 开始自底向上——建堆总代价是 $O(n)$ 而不是 $O(n\log n)$（越靠下的结点调整路径越短）。
例 2（排序阶段前两轮）.
① 交换 A[1]↔A[8]：$[9,45,78,23,17,65,53,\mathbf{87}]$；对前 7 个调整（9 下沉）⇒ $[78,45,65,23,17,9,53]$
② 交换 A[1]↔A[7]：$[53,45,65,23,17,9,\mathbf{78},\mathbf{87}]$；对前 6 个调整 ⇒ $[65,45,53,23,17,9]$
③ 继续重复（每次「取出」一个最大到后端）⇒ 最终 $[9,17,23,45,53,65,78,87]$ ✓。
排序阶段：$n-1$ 次交换 + 每次 $O(\log n)$ 调整 ⇒ 这一阶段是 $O(n\log n)$。
堆排序的复杂度与性质 时间：建堆 $O(n)$ + 排序 $O(n\log n)$ ⇒ 任何输入都是 $O(n\log n)$（不像快排有最坏退化）；空间 $O(1)$（原地，只用一个临时位）；不稳定（交换跳跃）。
考点延伸：「求前 k 大元素」用堆最优（$O(n + k\log n)$）；堆必须顺序存储（要按下标找孩子）。

07归并排序稳定 O(n log n)

二路归并思想：把序列看成 $n$ 个长度为 1 的有序段，两两合并成 $n/2$ 个长度 2 的有序段，再两两合并……共 $\lceil\log_2 n\rceil$ 趟后全局有序。
合并（Merge）是核心动作：两个有序段从头比较，谁小先取（相等取左——稳定的关键）。
void Merge(int A[], int low, int mid, int high) {
    int B[ ] = 辅助数组;                 /* 或用全局辅助数组 */
    for (int k = low; k <= high; k++) B[k] = A[k];   /* 复制 */
    int i = low, j = mid + 1;
    for (int k = low; k <= high; k++) {
        if (i > mid) A[k] = B[j++];              /* 左段取完 */
        else if (j > high) A[k] = B[i++];        /* 右段取完 */
        else if (B[i] <= B[j]) A[k] = B[i++];    /* 相等取左，保稳定 */
        else A[k] = B[j++];
    }
}
例（{49,38,65,97,76,13,27,49} 三趟全轨迹）.
趟段长结果
初始1[49][38][65][97][76][13][27][49]
第 1 趟2[38,49] [65,97] [13,76] [27,49]
第 2 趟4[38,49,65,97] [13,27,49,76]

复杂度：共 $\lceil\log_2n\rceil$ 趟、每趟合并 $O(n)$ ⇒ 任何输入都是 $O(n\log n)$；辅助空间 $O(n)$（这是它最大的代价）；稳定 ✓。

08基数排序非比较排序

思想（LSD：低位优先）：从个位到最高位，每趟按当前位把元素「分配」进 $r$ 个队列（0–9），再按队列顺序「收集」回序列——$d$ 趟后有序。不比较关键字大小，靠「分配 + 收集」。
例（{278,109,63,930,589,184,505,269,8,83} 三趟全轨迹）.

复杂度与适用 时间 $O(d(n+r))$（$d$ 位数、$r$ 基数/队列数）；空间 $O(r)$（队列）；稳定；

09外部排序I/O 为王

为什么需要：待排数据太大、内存装不下——只能分批装入内存排序再写回外存。瓶颈是磁盘 I/O（读写次数），一切优化都围绕「减少 I/O 趟数」。
两阶段流程：
① 生成初始归并段：把数据分块读入内存、内部排序后写回，得到 $r$ 个有序的「初始归并段」；
② 多趟归并：对 $r$ 个段做 $k$ 路平衡归并，每趟把段数缩小 $k$ 倍，直到合成一个有序文件。
归并趟数公式（必考计算） $$S=\lceil\log_k r\rceil$$ $r$ 为初始归并段数、$k$ 为归并路数。例：$r=100$、$k=5$ ⇒ $S=\lceil\log_5 100\rceil=\lceil2.86\rceil=3$ 趟；若 $k$ 提到 10 ⇒ $S=2$ 趟——加大 $k$ 是减少 I/O 的第一手段。
三个配套技术：
① 败者树：$k$ 路归并每次从 $k$ 个段头选最小，朴素比较要 $k-1$ 次；败者树（完全二叉树上的锦标赛）把每次选择的比较降到 $\lceil\log_2 k\rceil$ 次——让大 $k$ 的归并「内部不亏」；
② 置换-选择排序：生成初始段时不要求一次装满内存——利用「缓冲区换出比当前段最大还小的元素」，使初始段平均长度达到 $2w$（$w$ 为内存工作区大小），从而减少初始段数 $r$、减少趟数；
③ 最佳归并树：各初始段长度不等时，用 Huffman 思想（以段长为权、$k$ 叉合并）安排归并顺序使总 I/O 最小。若段数不满「$k$ 叉满树」要补虚段：当 $(r-1)\bmod(k-1)\ne0$ 时，补 $$(k-1)-\big[(r-1)\bmod(k-1)\big]$$ 个长度为 0 的虚段。例：$k=3$、$r=8$：$(8-1)\bmod 2=1\ne0$ ⇒ 补 1 个虚段（凑成 3 叉满树）✓。

10典型例题划分·堆·性质·计算

例 1（快排一趟划分手算）. $A=[46,79,56,38,40,84]$，枢轴取首元素 46：
① high 左行：84≥46 过、40<46 停 ⇒ A1←40；② low 右行：40 过、79>46 停 ⇒ A5←79；
③ high 左行：79 过、38<46 停 ⇒ A2←38；④ low 右行：38 过、56>46 停 ⇒ A4←56；
⑤ 指针相遇 ⇒ A3←46： $$\boxed{[40,38,\ \mathbf{46},\ 56,79,84]}$$ 验算：左边 40、38 全小于 46，右边全大于 46 ✓（左右半内部无需有序——这正是「一趟结果」的定义）。
例 2（堆顶删除后的第一次调整）. 大根堆 $[87,45,78,23,17,65,53,9]$，取走堆顶 87（末尾 9 换到堆顶）后调整：
① 9 与孩子 45、78 比较 ⇒ 78 上移；② 9 下探到 78 原位，与孩子 65、53 比较 ⇒ 65 上移；③ 9 落定： $$[78,45,65,23,17,9,53]$$ 观察：每一步都是「与较大的孩子交换」——堆调整的唯一法门。
例 3（性质快问快答）.
(a) 「比较次数与初始序列无关的排序」⇒ 简单选择排序（恒为 $\frac{n(n-1)}2$）、堆排序建堆的比较也有类似定性题；
(b) 「排序趟数与初始序列无关」⇒ 堆排序、归并排序（固定趟数）；冒泡（有 flag 相关）、快排（相关）；
(c) 「最坏 $O(n\log n)$ 且空间 $O(1)$」⇒ 堆排序（归并空间 $O(n)$、快排最坏 $O(n^2)$）；
(d) 「不稳定但平均最快」⇒ 快速排序。
例 4（外部排序计算）.
① $r=100$ 个初始段、$k=5$ 路归并：$S=\lceil\log_5 100\rceil=3$ 趟；
② $k=10$：$S=\lceil\log_{10}100\rceil=2$ 趟；
③ 最佳归并树：$k=3$、$r=8$ ⇒ $(8-1)\bmod(3-1)=1\ne0$ ⇒ 补 $(3-1)-1=1$ 个虚段；
结论链：减少 I/O = 「加大 $k$（配败者树）+ 增长初始段（置换选择）+ 最优归并次序（Huffman + 虚段）」。

易错点清单

  1. 稳定性口诀：「快些选堆」四个不稳定（快排、希尔、简单选择、堆排）；插入/冒泡/归并/基数稳定。
  2. 折半插入的假象：比较次数降到 $O(n\log n)$，但移动是瓶颈 ⇒ 总时间仍是 $O(n^2)$。
  3. 希尔的增量：最后一趟必须 $d=1$；且它不稳定（跨组交换）。
  4. 冒泡的最好情形：$O(n)$ 前提是「本趟无交换就停」的 flag 优化。
  5. 「快排一趟」的含义：只是枢轴归位、左小右大——两侧内部不保证有序。
  6. 快排最坏场景：输入基本有序/逆序 + 固定取首元素枢轴 ⇒ $O(n^2)$；随机枢轴/三数取中可避免。
  7. 快排的空间：递归栈 $O(\log n)$（平均），别答 $O(1)$。
  8. 简单选择的「恒定」：比较次数与初始无关；移动次数可以很少（最省移动）。
  9. 建堆不是 $O(n\log n)$：自底向上建堆总代价 $O(n)$；下标 0 起时孩子是 $2i+1/2i+2$，写代码别套错。
  10. 归并的空间：$O(n)$ 辅助数组——「时间优、空间劣」；外部排序的「归并趟数」是磁盘 I/O 概念，别与内部归并混淆。
  11. 基数排序：$O(d(n+r))$、稳定、与初始无关；「位数多、基数大」时退化。
  12. 「最坏 O(nlogn) + 空间 O(1)」：只有堆排序满足（快排最坏退化、归并空间 $O(n)$）——选择题标准答案。
