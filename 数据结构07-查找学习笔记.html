01基本概念与 ASL全章度量

查找：在数据集合中寻找满足条件的数据元素。
关键字：能唯一标识一个数据元素的数据项（值）。
查找表：静态查找表（只查不改：顺序、折半、散列）与动态查找表（查询 + 插入删除：BST、AVL、B 树、散列也可）。
平均查找长度（ASL）：查找过程中关键字比较次数的期望值——衡量查找算法优劣的核心指标： $$\text{ASL}=\sum_{i=1}^{n}P_i\,C_i$$ $P_i$ 是查第 $i$ 个元素的概率；$C_i$ 是找到它所需的比较次数。考试默认等概率（$P_i=1/n$）。
必须分开算两个数：$\text{ASL}_{\text{成功}}$（查到表中元素）与 $\text{ASL}_{\text{失败}}$（确认不在表中）——只写一个数的答案是残缺的。
本源例子（三个数的直观）：表 $\{10,20,30\}$ 顺序查找：查 10 比 1 次、20 比 2 次、30 比 3 次 ⇒ $\text{ASL}_{\text{成功}}=\dfrac{1+2+3}3=2=\dfrac{n+1}2$。失败时（如查 25）需把 3 个元素都比完 ⇒ 3 次。

02顺序查找最朴素

思想：从表的一端开始逐个比较——对无序/有序表都适用，链表也能用（这是它相比折半的独特优势）。
带哨兵的实现（从后往前扫）： 
typedef struct { ElemType *elem; int TableLen; } SSTable;
int Search_Seq(SSTable ST, ElemType key) {
    ST.elem[0] = key;                  // 0 号放哨兵
    int i;
    for (i = ST.TableLen; ST.elem[i] != key; i--)   // 从后往前
        ;                              // 循环内无需判越界（哨兵必命中）
    return i;                          // 返回 0 表示失败
}
哨兵的作用：把「边界判断」省掉一次——不必在循环里写 i >= 1 的条件（0 号哨兵必定让循环停下），这是经典的「以空间/设计换速度」。
例（ASL 完整推导）.
成功：等概率下，第 $i$ 个元素被查到时比较 $n-i+1$ 次（从表尾数）或 $i$ 次（从表头数，无哨兵）——两种计法平均相同： $$\text{ASL}_{\text{成功}}=\frac1n\sum_{i=1}^{n}i=\frac{n+1}2=O(n)$$ 失败：从表头扫（无哨兵）要比较 $n$ 次才能确认失败 ⇒ $\text{ASL}_{\text{失败}}=n$；从表尾带哨兵则要 $n+1$ 次（含哨兵）——以题目实现为准，最常考答案 $\dfrac{n+1}2$ 与 $n$。
有序表的福利：表中元素有序时，失败可以「提前刹车」（遇到比 key 大的元素即停）： $$\text{ASL}_{\text{失败}}^{\text{有序}}=\frac n2+\frac n{n+1}$$ （推导：$n+1$ 个失败区间中，第 $k$ 个区间需比较 $k$ 次左右，$k=1..n$ 与一个 $n$ 次 ⇒ 总和 $\frac{n(n+1)}2+n$，除以 $n+1$。）
一句话评价：顺序查找的优点是「零要求」（无序、链表均可）；缺点是 $O(n)$——正好与折半的「有序 + 顺序存储换 $O(\log n)$」形成对照。

03折半查找判定树必画

两个硬前提：① 表有序；② 顺序存储（必须能 $O(1)$ 取到中间元素——链表做不了折半！）。
int Binary_Search(SSTable L, ElemType key) {
    int low = 1, high = L.TableLen, mid;
    while (low <= high) {
        mid = (low + high) / 2;               // 向下取整
        if (L.elem[mid] == key) return mid;       // 命中
        else if (L.elem[mid] > key) high = mid - 1; // 去左半区
        else low = mid + 1;                        // 去右半区
    }
    return 0;                                  // 失败
}
时间复杂度 $O(\log_2 n)$——每比较一次候选区间减半。
折半查找判定树：把每次 mid 作为结点画出来，就得到一棵平衡二叉排序树：
· 每个内部结点 = 一次成功命中；每个空指针处 = 一个失败区间 ⇒ 失败结点共 $n+1$ 个（外部）；
· 树高 $h=\lceil\log_2(n+1)\rceil$ ⇒ 比较次数不超过 $h$；
· ASL 的算法：$\text{ASL}_{\text{成功}}=\dfrac1n\sum(\text{结点所在层数})$；失败比较次数 = 对应外部结点的父结点层数。
例（n = 11 的完整判定树与两个 ASL）. 表 $[1..11]$，mid 向下取整：
① 第一层：mid=6；第二层：mid=3、9；第三层：mid=1、4、7、10；第四层：mid=2、5、8、11？
让我按区间严格推：$[1,11]$ mid=6；$[1,5]$ mid=3；$[7,11]$ mid=9；$[1,2]$ mid=1；$[4,5]$ mid=4；$[7,8]$ mid=7；$[10,11]$ mid=10；$[2,2]$ mid=2；$[5,5]$ mid=5；$[8,8]$ mid=8；$[11,11]$ mid=11。
层数统计：第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 4 个（1+2+4+4=11 ✓）。 
                6
            /       \
          3           9
        /   \       /   \
       1     4     7     10
        \     \     \     \
         2     5     8     11
② ASL 成功： $$\text{ASL}_{\text{成功}}=\frac{1\times1+2\times2+3\times4+4\times4}{11}=\frac{33}{11}=3$$ ③ ASL 失败：失败结点（外部）12 个中，挂在第 3 层结点下的有 4 个（比较 3 次）、挂第 4 层下的 8 个（比较 4 次）： $$\text{ASL}_{\text{失败}}=\frac{4\times3+8\times4}{12}=\frac{44}{12}\approx3.67$$
秒算口诀：判定树高度 $h=\lceil\log_2(n+1)\rceil$（n=11 ⇒ ⌈log₂12⌉=4）；成功 ASL 一定介于 $\log_2(n+1)-1$ 与 $h$ 之间——满树时取到最小 $=\frac{n+1}n\log_2(n+1)-1$。

04分块查找索引顺序

思想：把表分成若干块——块间有序（第 $k$ 块所有元素都大于第 $k-1$ 块最大者）、块内无序（随意）；再建一张索引表（每块「最大关键字 + 起始地址」）。
查找两步：① 在索引表定块（顺序或折半）；② 在块内顺序查找。
例（分块结构示意）. 
表：  22  12  13 | 8   9  20 | 33  42  44 | 38  24  48
索引表：  [13 → 块1]  [20 → 块2]  [44 → 块3]  [48 → 块4]
（每块内：乱序；块与块之间：整体递增）
查 38：先扫索引表找第一块满足「最大关键字 ≥ 38」⇒ 第 3 块（44）；再在块内逐个比较 ✓。
例（ASL 推导与最优块长）. 设 $n$ 个元素均分成 $b$ 块、每块 $s=n/b$ 个：
① 索引表顺序查找：平均 $\dfrac{b+1}2$ 次；② 块内顺序查找：平均 $\dfrac{s+1}2$ 次；③ 合计： $$\text{ASL}=\frac{b+1}2+\frac{s+1}2=\frac{\dfrac nb+s}2+1\ \ge\ \sqrt n+1$$ （由均值不等式 $\dfrac nb+s\ge2\sqrt n$，等号在 $s=\sqrt n$ 时取到）——当每块长 $s=\sqrt n$、块数 $b=\sqrt n$ 时 ASL 最小，约 $\sqrt n+1$。
数值：$n=10000$ ⇒ 最优 $s=100$、$b=100$，$\text{ASL}_{\min}=50.5+50.5=101=\sqrt n+1$ ✓（比顺序查找的 5000 强、比折半的约 13 弱——但分块支持动态变化，这是它的价值）。
三种线性表查找对比：
算法ASL成功ASL失败前提适用
顺序查找$\frac{n+1}2$$n$无无序/链表
折半查找≈$\log_2(n+1)-1$≈$\log_2(n+1)$有序 + 顺序存储静态、频繁查找
分块查找$\frac{b+1}2+\frac{s+1}2$，最优 $\sqrt n+1$类似块间有序动态变化、折中

05二叉排序树（BST）动态查找

定义（递归）：或为空树；或满足——左子树上所有结点 < 根 < 右子树上所有结点，且左右子树也分别是 BST。
核心性质（必背）：中序遍历得到递增有序序列——这是判断一棵树是不是 BST 的最快方法。
查找（循环版）： 
BiTNode *BST_Search(BiTree T, ElemType key) {
    while (T != NULL && key != T->data)
        T = (key < T->data) ? T->lchild : T->rchild;  // 小往左、大往右
    return T;                        // NULL 表示失败
}
插入：从根开始比较，一路走到底——第一处空位就是插入点（重复关键字则插入失败）： 
int BST_Insert(BiTree &T, ElemType k) {
    if (T == NULL) {                 // 找到空位，挂上
        T = (BiTNode *) malloc(sizeof(BiTNode));
        T->data = k;  T->lchild = T->rchild = NULL;
        return 1;
    }
    else if (k == T->data) return 0;             // 已存在
    else if (k < T->data) return BST_Insert(T->lchild, k);
    else return BST_Insert(T->rchild, k);
}
删除的三种情况（高频考点）：
① 删除叶子：直接删；
② 删除只有一棵子树的结点：子树整体顶替；
③ 删除有两棵子树的结点：用它的中序直接前驱（左子树最大）或直接后继（右子树最小）替换数据，再递归删除那个前驱/后继（最终落回情况 ① 或 ②）。
例（建树与 ASL）. 依次插入 $\{45,\ 24,\ 53,\ 12,\ 37,\ 93\}$： 
          45
        /    \
      24      53
     /  \       \
   12    37      93
各结点层数：45(1)、24/53(2)、12/37/93(3) ⇒ $$\text{ASL}_{\text{成功}}=\frac{1+2+2+3+3+3}{6}=\frac{14}6\approx2.33$$ 观察：同一组关键字，插入顺序不同会得到不同形态的 BST——ASL 也随之不同（这是 BST 的软肋，引出 AVL）。
两种极端：插入序列本身有序（如 1,2,3,…,n）⇒ BST 退化成单链，查找 $O(n)$（最坏）；形态接近完全二叉树时 $O(\log n)$（最好）。BST 查找的时间取决于树形而不是结点数。

06平衡二叉树 AVL四种旋转

平衡因子：$\text{BF}(v)=h(\text{左子树})-h(\text{右子树})$。AVL 树要求所有结点 $|\text{BF}|\le1$——即「每个结点左右子树高度差不超过 1」的高度平衡 BST。
目标：把 BST 的树高压在 $O(\log n)$，代价是插入/删除时要旋转恢复平衡。
四种失衡情形与旋转（从插入点向上找第一个失衡结点，看插入落在它的哪边）：
情形插入位置（相对失衡点）恢复操作最小例（依次插入）
LL左孩子的左子树一次右单旋3, 2, 1 ⇒ 2(1,3)
RR右孩子的右子树一次左单旋1, 2, 3 ⇒ 2(1,3)
LR左孩子的右子树先左旋、再右旋3, 1, 2 ⇒ 2(1,3)
RL右孩子的左子树先右旋、再左旋1, 3, 2 ⇒ 2(1,3)
命名记忆：两个字母 = 「失衡点到插入点的前两步方向」：LL 左左、RR 右右、LR 左右、RL 右左。
例（完整建树：依次插入 50, 30, 60, 20, 40, 35）.
① 插 50、30（左）、60（右）、20（30 的左）、40（30 的右）——此时无失衡；
② 插 35（40 的左）：自底向上检查——40 平衡（BF=1）、30 平衡（BF=−1）、50 失衡（左子树高 3、右子树高 1，BF=2）；
③ 插入位置是 50 的左孩子(30) 的右子树 ⇒ LR 型：
  · 第一步：对 30 做左旋 ⇒ 40 顶上来（30 与 35 成为它的左子树部分）；
  · 第二步：对 50 做右旋 ⇒ 40 成为整棵树根； 
最终：          40
             /      \
           30        50
          /  \         \
        20    35        60
④ 验算：各结点 BF —— 20、35、60 为叶（0）；30：$1-1=0$；50：$0-1=-1$；40：$2-2=0$ ✓ 全部 $|\text{BF}|\le1$，恢复平衡且中序仍有序 ✓。
高度 h 的 AVL 最少结点数（选择题常客）：要让高度为 $h$ 的 AVL 结点尽量少，根的两棵子树高度只能是 $h-1$ 与 $h-2$： $$N(h)=N(h-1)+N(h-2)+1,\quad N(1)=1,\ N(2)=2$$
$h$1234567
最少结点 $N(h)$1247122033
反过来记结论：AVL 的高度一定在 $O(\log n)$ 量级、查找最坏 $O(\log n)$。

07红黑树（简述）考纲新增

红黑树：满足以下五条性质的二叉排序树（每个结点带红/黑颜色）：
① 每个结点非红即黑；
② 根结点是黑色；
③ 叶结点（外部 NIL）都是黑色；
④ 不存在两个连续的红结点（红结点的孩子必为黑）；
⑤ 从任一结点出发到其所有叶结点的路径上，黑结点数目相同（黑高相同）。
核心结论（为什么用它）：从性质 ④⑤ 可推出——最长路径不超过最短路径的 2 倍，因此红黑树的高度 $$h\le2\log_2(n+1)=O(\log n)$$ 查找、插入、删除全部 $O(\log n)$。
与 AVL 的分工：AVL 追求「高度严格平衡」（查询最快），红黑树只求「大致平衡」（插入删除时调整更少）——因此频繁增删场景选红黑树（C++ STL 的 map / Java TreeMap 底层都是红黑树），查询为主选 AVL。
插入调整直觉：新结点先染红；若违反「无连续红」，看插入点的叔叔结点颜色——叔叔红就「变色上移」，叔叔黑就「旋转 + 变色」（与 AVL 旋转同思想）。

08B 树与 B+ 树多路平衡查找树

$m$ 阶 B 树（多路平衡查找树）定义：
① 每个结点最多有 $m$ 棵子树、最多 $m-1$ 个关键字；
② 根结点若不是叶，至少有 2 棵子树；
③ 其他非叶结点至少有 $\lceil m/2\rceil$ 棵子树（即至少 $\lceil m/2\rceil-1$ 个关键字）；
④ 所有叶结点都在同一层（绝对平衡，不像 AVL 只看高度差）；
⑤ 结点内关键字有序，子树中的关键字落在相邻两关键字之间的区间（多路，一次比较排除一大批）。
高度的上下界（含 n 个关键字） 最小高度（每结点都塞满 $m-1$ 个关键字）：$h\ge\log_m(n+1)$；
最大高度（每结点都只有最少分叉 $\lceil m/2\rceil$）： $$h\le\log_{\lceil m/2\rceil}\frac{n+1}2+1$$
例（3 阶 B 树——即 2-3 树——的插入与分裂）. 依次插入 1, 2, 3, 4, 5（3 阶：每结点最多 2 个关键字、3 棵子树）：
插入动作树形（用括号表示结点）
1根只有 1[1]
2塞进根[1, 2]
3根溢出（3 个关键字）⇒ 分裂：中间 2 上移成新根[2] → 左 [1]、右 [3]
4比 2 大比 3 大 ⇒ 进右结点[2]；左 [1]、右 [3, 4]
5右结点溢出（3,4,5）⇒ 分裂：中间 4 上移；根变 [2, 4][2, 4]；子 [1]、[3]、[5]
分裂要点：结点超过 $m-1$ 个关键字时，取中间关键字上移到双亲，左右两半各成一个结点——树是「自底向上长高」的 ✓。
删除（简述）：删到关键字不足 $\lceil m/2\rceil-1$ 时——能向兄弟借就借（经双亲中转关键字），借不到就与兄弟合并（双亲关键字下拉），可能连锁。
B+ 树：B 树的变体，专门服务「数据库/文件的索引」：
① 所有关键字都出现在叶结点，叶结点包含「关键字 + 记录指针」；
② 非叶结点只当索引（存关键字副本 + 子树指针）；
③ 叶结点之间用指针连成有序链表——支持顺序访问与范围查询。
维度B 树B+ 树
关键字位置各层结点都存全部在叶；非叶只做索引
查找命中点可能在非叶命中提前结束必须走到叶（每次查找路径等长）
叶间链无有（顺序遍历、范围查询 O(1) 起跳）
树高相对高更「矮胖」（非叶不存数据，单结点扇出更大）
典型应用文件系统索引数据库索引（MySQL 聚簇索引）
记忆：「B 树 = 每层都可能中奖；B+ 树 = 一切答案在叶，叶子还串成链」——范围查询为什么偏爱 B+，一句话就通了。

09散列表冲突与 ASL

散列表（哈希表）：用哈希函数 $H(key)$ 直接计算出存储地址——理想情况一次到位、$O(1)$ 平均查找。
冲突：$H(key_1)=H(key_2)$ 但 $key_1\ne key_2$（同义词）——冲突不可避免，只能「设计好函数 + 定好处理策略」。
常见哈希函数：
① 除留余数法（最常用）：$H(key)=key\bmod p$，$p$ 取「不大于表长 $m$ 的最大质数」（减少冲突）；
② 直接定址法：$H(key)=a\cdot key+b$（无冲突，但要求关键字连续）；
③ 数字分析法、平方取中法、折叠法——了解名字与适用即可。
冲突处理两大家族：
① 开放定址法：$H_i=(H(key)+d_i)\bmod m$——线性探测 $d_i=1,2,3,\dots$；平方探测 $d_i=\pm1^2,\pm2^2,\dots$；再散列/伪随机。特点：同义词与非同义词都可能挤在一起（堆积现象）；删除不能直接置空（要用「墓碑」标记，否则截断探测链）。
② 拉链法（链地址法）：同义词挂成一条链表，槽内放链头指针。特点：删除方便、无堆积、装填因子可大于 1。
例 1（线性探测全流程：$H(k)=k\bmod 13$，表长 16）. 关键字依次 $\{19,14,23,1,68,20,84,27,55,11,10,79\}$：

装填因子 $\alpha=n/m$（关键字数/表长）：$\alpha$ 越大，冲突越多、ASL 越大——散列表的平均查找长度只与 $\alpha$ 有关，与 n 的绝对值无关（这是散列的美妙之处）；开放定址要求 $\alpha<1$，拉链法可以 $\alpha>1$。

10典型例题ASL·删除·旋转·判定

例 1（满判定树 ASL 秒算）. 15 个元素等概率折半查找（恰好构成满二叉树）： $$\text{ASL}_{\text{成功}}=\frac{1\times1+2\times2+4\times3+8\times4}{15}=\frac{49}{15}\approx3.27$$ 通用公式：对于满判定树（$n=2^h-1$）： $$\text{ASL}=\frac{(n+1)\log_2(n+1)-n}{n}\ \longrightarrow\ h-1\ \text{量级}$$ （比顺序查找 8 快一倍以上——这就是 $O(\log n)$ 的威力。）
例 2（BST 删除双孩子结点：两种替换都演示）. 树：45(24(12,37), 53(∅,93))，删除 24：
① 24 有两棵子树（12 与 37），取中序直接后继 37（右子树最小）替换：24 的位置放 37 ⇒ 45(37(12,∅), 53(∅,93))；
② 或取中序直接前驱 12 替换：24 的位置放 12 ⇒ 45(12(∅,37), 53(∅,93))。
两种结果都是合法 BST（中序仍有序）——考试给步骤要求时按题目指定（王道默认「右子树最小」）。
例 3（AVL 旋转判断练习）. AVL 树：30(20(10,25), 40)；插入 22（走到 25 的左孩子）：
① 检查平衡因子：25：0→1 ✓；20：左(10)1、右(25)2 ⇒ BF = −1 ✓；30：左子树高 3、右 1 ⇒ BF=2 失衡；
② 插入位置 = 30 的左孩子(20) 的右子树 ⇒ LR 型；
③ 先对 20 左旋 ⇒ 25 顶上来（20 连同左子树成为 25 的左孩子、原 25 的左孩子 22 转挂到 20 的右侧）；再对 30 右旋 ⇒ 25 成整树根： 
最终：        25
           /      \
         20        30
        /  \         \
      10    22        40
④ 验算 BF：20：$1-1=0$；30：$0-1=-1$；25：$2-2=0$ ✓。
例 4（B 树 / B+ 判断四连）.
(a)「3 阶 B 树的非叶非根结点至少有 2 个关键字」⇒ 错：至少 $\lceil 3/2\rceil-1=1$ 个关键字；
(b)「B 树所有叶结点在同一层」⇒ 对（绝对平衡的定义）；
(c)「B+ 树的非叶结点中也存放数据记录」⇒ 错：非叶只存索引，记录只在叶；
(d)「范围查询（找到 ≥k 的所有记录）B+ 比 B 方便」⇒ 对（叶链表顺次扫描）。

11决策流程与易错点

查找题
├─ ASL 计算
│   ├─ 先问：成功还是失败？分开算
│   ├─ 顺序：成功 (n+1)/2；失败 n
│   ├─ 折半：画判定树 → 数层数
│   └─ 散列：逐 key 数比较次数 → 求和 / n
├─ 折半查找
│   ├─ 判定树 = 平衡 BST；失败结点 n+1 个
│   ├─ 失败比较次数 = 外部结点的父层数
│   └─ 前提：有序 + 顺序存储（链表不行）
├─ BST
│   ├─ 建树：小左大右、空位即插入点
│   ├─ 删除双孩子：前驱/后继替换后递归删
│   └─ 形态取决于插入顺序 → ASL 变化
├─ AVL：向上找第一个失衡点 → 看方向定 LL/RR/LR/RL → 旋转
├─ B 树：阶与上下限（ceil(m/2)）；分裂=中间上移；B+ 差异清单
└─ 散列：函数选质数模；冲突两法；删除要墓碑

易错点清单

  1. ASL 必分成功/失败：只给一个数会被扣分；失败 ASL 的分母是失败区间数。
  2. 折半只限顺序存储：「链表也能折半」一定错（无法 $O(1)$ 定位 mid）。
  3. 判定树失败结点 $n+1$ 个：失败比较次数按「外部结点之父的层数」数，不是外部结点本身的层数。
  4. mid 取整方向：$(low+high)/2$ 向下取整——取整方向不同，判定树形状就不同。
  5. 分块查找：块间有序、块内可以无序；最优块长 $s=\sqrt n$。
  6. BST 删除双孩子：是「替换数据 + 递归删除前驱/后继」，不是直接删。
  7. BST 的 ASL 不唯一：取决于插入顺序；有序插入退化成链（$O(n)$）。
  8. AVL 旋转类型看「失衡点」不是「根」：从插入点向上找第一个失衡结点，再判断 LL/RR/LR/RL。
  9. B 树下限是 $\lceil m/2\rceil$：子树数下限 $\lceil m/2\rceil$、关键字下限 $\lceil m/2\rceil-1$——别把二者混写。
  10. B+ 必到叶：非叶命中也不能停；范围查询靠叶链表。
  11. 开放定址删除：不能直接置空（会截断探测链），必须用标记位。
  12. 散列 ASL 与 n 无关：只随装填因子 $\alpha$ 变化——比较对象是 $\alpha$ 不是元素个数。

12速查表与能力自查

主题结论
ASL 定义$\sum P_iC_i$；成功/失败分开；等概率 $P_i=1/n$
顺序查找成功 $\frac{n+1}2$；失败 $n$（有序表失败 $\frac n2+\frac n{n+1}$）；无序/链表可用
折半查找$O(\log n)$；判定树 $h=\lceil\log_2(n+1)\rceil$；失败结点 $n+1$；只能顺序存储
分块查找ASL $=\frac{b+1}2+\frac{s+1}2$；最优 $s=\sqrt n$ ⇒ $\sqrt n+1$
BST中序有序；插入=空位；删除三类（双孩子用前驱/后继替换）；ASL 依赖树形
AVL$|BF|\le1$；LL=右旋、RR=左旋、LR=先左后右、RL=先右后左；$N(h)=N(h-1)+N(h-2)+1$
红黑树五性质；$h\le2\log_2(n+1)$；增删频繁选它
B 树m 阶：子树 ≤m、关键字 ≤m−1；非根非叶子树 ≥⌈m/2⌉；叶同层；分裂=中间上移；$h\ge\log_m(n+1)$
B+ 树关键字全在叶、叶有链；必查到叶；范围查询强
散列表$H=key\bmod p$（质数）；开放定址（线性/平方）vs 拉链；ASL 由 $\alpha$ 决定
经典算例折半 n=11：成功 3、失败 44/12；散列例：ASL 成功 2.5（线性）、9/7（拉链）
一句话总纲：查找全章就干一件事——数比较次数：线性表数位置、判定树数层数、BST/AVL 数树高、B 树数结点内比较加层数、散列逐 key 数探测——ASL 是贯穿一切的那根线。
