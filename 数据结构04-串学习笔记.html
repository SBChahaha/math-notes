01串的基本概念与存储结构概念

串（字符串）：由零个或多个字符组成的有限序列，记 $S="a_1a_2\cdots a_n"$；$n$ 为串长，$n=0$ 时是空串。
· 子串：串中任意个连续字符组成的子序列；主串：包含子串的串；
· 字符在串中的位置从 1 开始计；子串出现在主串中的位置 = 其第一个字符在主串中的位置；
· 串相等：长度相同且各位字符一一相同；
· 辨析：空串（长度 0）与空格串（由空格组成，长度 ≥ 1）完全不同——「空串是任意串的子串」。
三种存储结构：
① 定长顺序存储： 
#define MAXLEN 255
typedef struct {
    char ch[MAXLEN];      // 每个分量存一个字符（下标 0 不用，从 1 开始）
    int length;           // 串长
} SString;
超出 MAXLEN 时「截断」——这是与顺序表一样的固有问题；
② 堆分配存储：起始地址 + 长度，用 malloc 按需分配（长串更合适）；
③ 块链存储：每个结点存多个字符（结点大小可调）——存储密度高，但操作与链表一样繁琐。

02朴素模式匹配（BF）暴力对照

BF（Brute-Force）思想：把模式串 T 与主串 S 从左到右逐字符比较——失配时主串指针回溯：从本趟起点的下一个位置重新开始（i 退到 $i-j+2$），j 回到 1。
例（BF 代码，定长顺序存储）. 
int Index_BF(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) { i++; j++; }   // 当前字符相同：齐步走
        else { i = i - j + 2; j = 1; }          // 【回退】模式串右滑一位
    }
    if (j > T.length) return i - T.length;      // 匹配成功，返回起始位置
    else return 0;                              // 失败
}
回退公式解读：本趟从 $i-j+1$ 开始比较，失配后从它的下一个位置 $i-j+2$ 重启——主串指针往回走就是 BF 慢的根源。
例（BF 的最坏情形）. 主串 $S="00000000001"$（9 个 0 + 1），模式串 $T="00001"$。
① 每趟都要比较到 T 的第 5 位才失配 ⇒ 每趟 5 次比较；
② 需要 $(n-m+1)$ 趟 ⇒ 总比较约 $5(n-4)$ 次；
③ 一般化：$S$ 形如 $0\cdots01$、$T$ 形如 $0\cdots01$（前面全 0）时，每趟几乎比完整个 T ⇒ $$T_{\text{worst}}(n,m)=O(nm)$$ 对照：一般乱序文本下平均接近 $O(n+m)$，但 408 问「最坏」时必须答 $O(nm)$。
BF 的两个结论（选择题原话）：① 最坏时间复杂度 $O(nm)$（$n,m$ 为主串、模式串长度）；② 每趟失配后模式串只右移一位——「笨」在不肯多滑，KMP 就是让它「按自己的规律多滑几步」。

03KMP 原理：最长公共前后缀思想核心

KMP 的目标：让主串指针 i 永不回溯——失配时只把模式串向右「按自己的规律」滑动，j 退到一个合适的位置继续比。
为什么能做到：失配前已有 T[1..j−1] 与主串（以 i 结尾的一段）完全相等；于是「T 的前缀」与「主串已匹配段的后缀」中相同的部分可以直接复用——只需研究模式串自身的前后缀重合情况。
三个术语（以 T = "abaab" 为例）：
· 前缀：从第一个字符开始、不包含最后一位的连续子串：a、ab、aba、abaa；
· 后缀：以最后一个字符结尾、不包含第一位的连续子串：b、ab、aab、baab；
· 最长公共前后缀：两边都出现且长相等的最大者——这里 "ab"（长度 2）。
约定：前后缀必须是真前缀/真后缀（不能取整个串）。
next 数组的含义（王道约定） $$\text{next}[j]=1+\big(T[1..j-1]\ \text{的最长公共前后缀长度}\big)$$ 即：当 T 的第 j 位与主串失配时，下一步用 T 的第 next[j] 位与主串当前位继续比较。
两个必背特例：next[1] = 0（第一位就失配 ⇒ 特殊处理：主串右移一位、j 复位）；next[2] = 1（前串只有一个字符，无真公共前后缀）。

例（直观理解滑动）. T = "abaabc"，在主串某处已匹配前 3 位 "aba"、第 4 位失配：
① "aba" 的最长公共前后缀是 "a"（长 1）⇒ next[4] = 2；
② 于是直接把 T 滑到让 T 的第 2 位对齐主串当前位置——因为模式串前 3 位 "aba" 与主串匹配段相同，滑 1 位后 T[2..3]="ba" 与主串尾部 "ba" 天然对上，无需回头重比；
③ 对照 BF：BF 会把主串指针退回、从 T[1] 重新比——这正是被省下的浪费 ✓。

04next 数组的求法手算必过关

方法一：定义法（稳，推荐先掌握）——对每个 j 独立计算：
① next[1] = 0；
② 对 $j\ge2$：写出 T[1..j−1]，找其最长公共前后缀长度 $L$，则 next[j] = $L+1$。
例 1（定义法全过程：T = "abaabc"）.
$j$考察串 T[1..j−1]最长公共前后缀长度next[j]
1（无前串）——0固定
2a无（真前后缀不存在）01固定
3ab无01
4abaa12
5abaaa12
6abaabab23
结论：next = $\{0,\ 1,\ 1,\ 2,\ 2,\ 3\}$（j = 1…6）✓。
方法二：递推法（快，会流程图思想）——已知 next[j] = k，求 next[j+1]：
① 比较 $T[j]$ 与 $T[k]$：相等 ⇒ next[j+1] = k+1；
② 不等 ⇒ 令 $k = \text{next}[k]$ 继续比较（不断往前跳）；
③ 若 $k$ 退到 0 ⇒ next[j+1] = 1。
例 2（递推法验证「abaabc」）. 已知 next[1]=0、next[2]=1：
· 求 next[3]（j=2, k=next[2]=1）：T[2]=b vs T[1]=a ✗ ⇒ k=next[1]=0 ⇒ next[3]=1 ✓；
· 求 next[4]（j=3, k=next[3]=1）：T[3]=a vs T[1]=a ✓ ⇒ next[4]=1+1=2 ✓；
· 求 next[5]（j=4, k=next[4]=2）：T[4]=a vs T[2]=b ✗ ⇒ k=next[2]=1：T[4]=a vs T[1]=a ✓ ⇒ next[5]=2 ✓；
· 求 next[6]（j=5, k=next[5]=2）：T[5]=b vs T[2]=b ✓ ⇒ next[6]=3 ✓。
与定义法结果完全一致——两种方法互为验算。
get_next 递推代码（王道标准）： 
void get_next(SString T, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            i++;  j++;
            next[i] = j;          // 递推核心：next[i] = j+1 的位置
        } else {
            j = next[j];          // 失配：j 往前跳
        }
    }
}

05KMP 匹配过程与代码主串不回溯

匹配代码（与 BF 的差别只有一行）： 
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) { i++; j++; }
        else j = next[j];        // 【KMP 核心】i 不动，j 按 next 滑
    }
    if (j > T.length) return i - T.length;
    else return 0;
}
/* 用法：get_next(T, next); Index_KMP(S, T, next); */
与 BF 对比：BF 失配执行 i = i-j+2; j = 1（主串回退）；KMP 只执行 j = next[j]——主串指针只进不退，这是全部性能优势的来源。
例（KMP 全程轨迹）. 主串 $S=$"abacabaabc"（长 10），模式 $T=$"abaabc"，next = {0,1,1,2,2,3}。

观察：第 4–6 步主串指针一直停在 4——「滑了 3 次」全在模式串内部完成，这就是「不回溯」的样子。
复杂度对比（必背）
算法主串指针最坏时间额外空间
BF（朴素）回溯$O(nm)$$O(1)$
KMP不回溯$O(n+m)$$O(m)$（next 数组）
理解要点：i 从 1 增到 n，总增量 $O(n)$；j 的每次回退都「消耗」此前累积的匹配长度，均摊 $O(1)$——所以匹配是 $O(n)$，求 next 是 $O(m)$。

06nextval：KMP 的优化消除无效比对

为什么还要优化：若 $T[j]=T[\text{next}[j]]$，那么按 next 滑过去后，与主串当前位置比较的还是同一个字符——必然再次失配、白比一次。把这类「字符重复」直接继承，得到 nextval（优化的 next）。
nextval 求法：
① nextval[1] = 0；
② 对 $j\ge2$：比较 $T[j]$ 与 $T[\text{next}[j]]$——相同 ⇒ nextval[j] = nextval[next[j]]；不同 ⇒ nextval[j] = next[j]。
例 1（T = "abaabc"）. 已知 next = {0,1,1,2,2,3}：
jT[j]next[j]T[next[j]]比较nextval[j]
1a0——0
2b1a≠1（取 next）
3a1a=0（继承 nextval[1]）
4a2b≠2
5b2b=1（继承 nextval[2]）
6c3a≠3
结论：nextval = {0, 1, 0, 2, 1, 3}。
例 2（T = "aaaab"：重复字符的极端情形）. next = {0,1,2,3,4}： · j=2：a vs T[1]=a 相等 ⇒ 继承 ⇒ 0；
· j=3：a vs T[2]=a 相等 ⇒ 继承 nextval[2] = 0；
· j=4：a vs T[3]=a 相等 ⇒ 继承 = 0；
· j=5：b vs T[4]=a 不等 ⇒ 取 next = 4。
结论：nextval = {0, 0, 0, 0, 4}——失配时一步滑到底，避免了「aaaa」连续四次无效比较 ✓（这正是优化的价值）。
get_nextval 递推代码： 
void get_nextval(SString T, int nextval[]) {
    int i = 1, j = 0;
    nextval[1] = 0;
    while (i < T.length) {
        if (j == 0 || T.ch[i] == T.ch[j]) {
            i++;  j++;
            if (T.ch[i] != T.ch[j])
                nextval[i] = j;          // 不同：与 next 相同
            else
                nextval[i] = nextval[j]; // 相同：继承
        } else
            j = nextval[j];
    }
}
轨迹（"abaabc"）：i=1→…→ 依次写入 nextval[2]=1、nextval[3]=nextval[1]=0、nextval[4]=2、nextval[5]=nextval[2]=1、nextval[6]=3 ⇒ {0,1,0,2,1,3} ✓ 与手算一致。

08决策流程与易错点

串匹配题
├─ 手算 next / nextval
│   ├─ next：next[1]=0；next[j] = T[1..j−1] 最长公共前后缀长度 + 1
│   ├─ 递推验证：k=next[j]，比 T[j] 与 T[k]（失配则 k=next[k] 再比）
│   ├─ nextval：比 T[j] 与 T[next[j]]——同 ⇒ 继承 nextval[next[j]]；异 ⇒ 取 next[j]
│   └─ 必查固定值：next[2]=1；nextval[1]=0
├─ 模拟 KMP
│   ├─ 主串指针 i 永不回退
│   ├─ 失配：j = next[j]（或 nextval[j]）
│   └─ j==0 特殊：i++、j=1
└─ 复杂度回答
    ├─ BF：最坏 O(nm)
    └─ KMP：O(n+m)，空间 O(m)

易错点清单

  1. 「真」前后缀：不能取整个串——「abab」的公共前后缀里，"abab" 自己不算。
  2. 固定值先写：next[1]=0、next[2]=1；nextval[1]=0——开题先落笔，防止连锁算错。
  3. 「最长」公共前后缀：有多个重合时取最长（"ababa" 取 "aba" 不是 "a"）。
  4. nextval 比较对象：T[j] 与 T[next[j]]（拿 next 值当索引去取字符），不是与 T[j−1] 比。
  5. 两种求法互验：定义法结果 = 递推法结果；只对了一个说明过程有误。
  6. 模拟时 i 不动：失配后主串指针停在原地——写轨迹表时最容易「手滑回退」。
  7. j==0 是特殊分支：意味着「模式串第一位都匹配不上」，处理为 i++、j=1（此时主串前进一位）。
  8. 复杂度问「最坏」：BF 答 O(nm) 不是 O(n+m)；KMP 稳定 O(n+m)。
  9. 返回位置公式：王道 1-indexed 代码返回 $i-\text{len}(T)$（成功时 i 已多走一格）；下标从 0 的自拟代码要相应减 1。
  10. next 数组下标从 1 开始：next[0] 不用；与前面章节「下标从 0」的习惯不同，别混。

09速查表

主题结论
串的基本量空串（长 0）≠ 空格串；子串连续；位置从 1 起
BF 复杂度最坏 $O(nm)$；失配时 i 回退到 $i-j+2$、j=1
next 定义next[j] = 1 + T[1..j−1] 的最长公共前后缀长度；next[1]=0、next[2]=1
next 递推（已知 next[j]=k 求 next[j+1]）比 T[j] 与 T[k]：同 ⇒ k+1；异 ⇒ k=next[k] 再比；k 到 0 ⇒ 1
nextvalT[j]==T[next[j]] ⇒ nextval[j]=nextval[next[j]]；否则 = next[j]；nextval[1]=0
KMP 复杂度匹配 $O(n)$ + 求 next $O(m)$ ⇒ 总 $O(n+m)$，空间 $O(m)$
经典算例 ①"abaabc"：next = {0,1,1,2,2,3}；nextval = {0,1,0,2,1,3}
经典算例 ②"aaaab"：next = {0,1,2,3,4}；nextval = {0,0,0,0,4}
经典算例 ③"ababaa"：next = {0,1,1,2,3,4}；nextval = {0,1,0,1,0,4}
一句话总纲：KMP 的全部秘密藏在「模式串自己的最长公共前后缀」里——next 决定「失配后 j 退到哪」，nextval 顺手消掉「同字符白比」；模拟时牢记主串指针只进不退。
